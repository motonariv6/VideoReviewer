# VideoReviewer

VideoReviewerは、ローカル環境にある動画ファイルを対象として、動画再生・評価・タグ付け・コメント記録・タイムライン引用メモの作成、および複数レビュアー間でのレビューデータのインポート/エクスポートを行うWebアプリケーションです。

本アプリは、単なるローカル動画プレイヤーではなく、将来的な**外部アプリケーションとの連携を通じた「自然言語による動画のセマンティック検索（ハイブリッド検索）」**の実現に向けて、動画ごとに正確で豊富な構造化メタデータ（評価・タグ・時系列メモ）をローカルに蓄積することを目的として設計されています。

---

## 1. Current Status (開発状況)

現在、以下のコア機能が実装されており、すべての自動テストを通過しています。

* **ローカル動画フォルダ参照と再帰スキャン**: ブラウザの File System Access API を使用し、ローカルの指定フォルダとその配下のサブフォルダを高速かつ再帰的にスキャンします。
* **SHA-256 動画 Identity 技術**: 動画ファイルそのものの全データから算出した 64 文字の小文字 16 進数 SHA-256 ハッシュ値（`contentHash`）を正本として、アセットを一意に識別します。
* **Provisional (暫定) から Full Hash 確定の検証処理**: スキャン時は部分ハッシュ等で仮特定（`provisional`）を行い、バックグラウンドのワーカースレッド（Web Worker）で非同期に全体の SHA-256 を計算・確定（`completed`）させます。
* **ファイル移動・再接続時の Identity 維持**: 動画ファイルの場所（フォルダ階層やファイル名）が変更されても、ハッシュ値が一致すれば評価メタデータは失われません。
* **アーカイブ (退避) と完全削除（Cascade Deletion）**: ファイルが見つからない場合に一時的に非表示（アーカイブ）にする機能と、アセットおよび関連するレビュー・タグ・コメント・画像をデータベースから一括してカスケード削除する設計となっています。
* **動画ごとのカスタムポスター画像管理**:
  自動生成されたサムネイルとは別に、ユーザーが任意の画像（例: パッケージ画像など）を「カスタムポスター」として設定可能。
  * **表示優先順位**: `customPosterId` (カスタムポスター) -> `thumbnailId` (自動生成サムネイル) -> `thumbnailUrl` (Base64) -> fallback SVG の順で優先表示。
  * **Fallback**: カスタムポスターを削除した場合は、自動的に自動生成サムネイル表示へと安全に復帰。
  * **保護**: データベース全体の ZIP バックアップ（`images/posters/` 配下に格納）および復元対象に含まれますが、プライバシーおよび軽量化のため **Shared Review Package（エクスポートデータ）には絶対に混入しない**設計です。
* **総合評価の入力**: A〜E の 5 段階（DB 上では整数 1〜5 として保持）の総合評価に対応。
* **最大 6 項目の詳細評価基準（Criterion Ratings）**: 設定画面から詳細評価項目（星評価）を追加・編集・並べ替え可能です。ジャンルごとの評価テンプレートを切り替えることも可能です。
* **タグ（Tags）およびタイムライン引用メモ（Timeline Notes）**: タグの入力（IME Enter 確定バグ対策済み）、再生時間と連動したタイムラインコメントの記録に対応。
* **表示用カスタムタイトル (`displayTitle`)**: ファイル名とは別に、管理用の表示用タイトルを設定・保存できます。
* **データベース Schema v4 (複数レビュアー対応)**: データベースはバージョン 4 であり、1 つの動画アセットに対して複数のレビュアーの評価データを管理できます。
* **レガシーデータ互換正規化 (Schema Canonicalization)**: 起動時にレガシーな `template-*` ID を安全かつ決定論的にアトミックマージ（名寄せ）および正規化する機能を実装。予期せぬ不整合データもデータベース起動時に自動で補完・クリーンアップされます。
* **Shared Review Package v1 仕様での共有**: 他のユーザーの作成したレビューデータをインポート/エクスポートする機能。インポートされた他者のレビューは誤操作防止のため **完全読み取り専用 (Read-Only)** として保護されます。
* **保留レビュー（Pending Shared Review）と自動再紐付け**: インポート時に対象動画ファイルがローカルに存在しない場合、一時的に保留テーブルに格納し、後日フォルダスキャンや動画追加で SHA-256 が一致した時点で自動かつアトミックに再紐付け（昇格）を行います。
* **複数レビュアーの集約 UI（Aggregate UI）**: 同一動画に対する自分と他者のレビューをマージし、平均評価点・統合タグ（付与ユーザー内訳ツールチップ付き）・タイムラインコメントをマージして時系列順に一覧表示します。
* **タグマスタ管理（削除・検索・関係カスケード解除）**: 設定画面から登録されているタグ一覧を表示し、タグ名による絞り込み・検索や、不要なタグの削除を行えます。使用中のタグを削除した場合は、対象の全レビュー（自分およびインポート他者双方）からのタグ紐付けが安全かつカスケードに解除されます。
* **ロールバック保護機能付きバックアップ/復元**: データベース全体の ZIP バックアップ、および復元時の例外検知に伴う一括ロールバック処理をサポートしています。
* **GitHub Actions CI による品質保証**:
  `pull_request` および `push` to `main` をトリガーとして Node.js 22 + Chrome Headless による 389 件の自動テストを自動実行する CI 環境（`.github/workflows/test.yml`）を導入。`main` ブランチは Ruleset で保護されており、CI が PASS していない PR や直接の push を制限する堅牢な開発プロセスを敷いています。

## 2. Core Concepts (コアコンセプト)

### Video Identity (動画の一意性)
VideoReviewer において、動画の identity は**「ファイル内容全体の SHA-256 ハッシュ値（64文字の小文字16進数）」**のみによって決定されます。
以下の要素は**動画の Identity として一切使用されません。**
* ファイル名 (`fileName`)
* 相対ファイルパス (`relativePath`)
* 親フォルダ階層 (`directoryId`)
* 表示用カスタムタイトル (`displayTitle`)

これにより、ユーザーがローカルファイルを整理するためにフォルダ構成を変更したり、ファイル名をリネームしたり、ドライブ間を移動させたりした場合でも、アプリが再スキャン時に同一のハッシュ値を見つけ出すことで、これまでに記録された評価やメモをシームレスに維持し続けます。

#### ハッシュ計算の流れ
1. **Quick Hash (候補抽出)**: スキャン時にはファイルのサイズと、ファイルの一部を利用した `quickHash` によりマッチ候補を絞り込みます（この段階では未確定の `provisional` 状態）。
2. **Full Content Hash (SHA-256 確定)**: バックグラウンドの Web Worker がメインスレッドをブロックすることなく、ファイル全体の SHA-256 値を順番に精査します。計算が正常に完了した段階でハッシュ値は `completed` ステータスとなり、アセットの Identity が確定します。

### Local-first (ローカルファースト)
本アプリケーションはブラウザの Sandbox 環境に配慮しつつ、ローカル動画ファイルへのアクセスを `DirectoryHandle` / `FileHandle` の保持を通じて行います。
動画ファイルそのものをアプリケーション内の DB に複製・コピーすることはなく、現在の実装では動画ファイル自体を外部サービスへ自動送信しない設計となっています。

## 3. Review Model (レビューデータ構造)

Schema v4 において、レビュー関連の評価データは「誰がそれを記述したか」という レビュアー情報（`reviewerId`）に強固に結びついています。データは以下の 2 種類に大別されます。

### Local Owner Review (自分のレビュー)
ローカルマシンのオーナー（`isLocal: true` のレビュアー）が作成したデータであり、すべての項目が編集可能です。
* **総合評価スコア** (`overallScore` / 1〜5 の整数)
* **個別評価項目スコア** (`criterion_ratings`)
* **ジャンル / 評価テンプレート** (`genreId`)
* **付与したタグ** (`review_tags`)
* **総評フリーコメント** (`comment`)
* **タイムライン引用メモ** (`timeline_notes`)

### Imported Review (他者から取り込んだ共有レビュー)
共有機能（JSON インポート）経由で取り込まれた他ユーザーのデータです。データの整合性を維持するため、**完全な読み取り専用 (Read-Only) として保護されます。**
また、他者との共有範囲は以下の項目に制限されており、プライバシーやファイルシステムに関わる項目は共有・公開されません。
* **共有される情報**: 総合評価スコア、付与タグ、タイムライン引用メモ
* **共有されない情報 (非表示・エクスポート不可)**: 個別項目スコア、総評フリーコメント、選択ジャンル、テンプレート情報、カスタム表示タイトル (`displayTitle`)、サムネイル画像、ローカルファイル絶対・相対パス、DirectoryHandle情報

## 4. Review Sharing (レビューの共有フロー)

### Shared Review Package (v1)
他ユーザーとのデータ交換フォーマットとして、標準仕様化された JSON フォーマット **Shared Review Package (v1)** を使用します。
この共有用 JSON ファイルは、1 つのパッケージで複数の作品レビューを一括して含めることができる共通フォーマットです。
* `items.length = 1` の場合: 単一の動画レビューのみを共有 (単体エクスポート)
* `items.length > 1` の場合: 選択した複数の動画レビューを一括共有
* 全件選択の場合: ライブラリ内のすべての動画レビューを一括共有

### 処理フローの概念図

```text
Local Review (作成・編集)
    ↓
Export 選択
    ↓
Shared Review Package v1 (JSON ダウンロード)
    ↓ (他ユーザーによるインポート)
JSON Schema Validation / 定数上限の検証
    ↓
SHA-256 (contentHash) マッチング
   ↙       ↘
[Match: 動画あり]      [No Match: 動画なし]
 ↓                      ↓
Imported Review        Pending Shared Review (保留テーブルへ保存)
として DB へ即時登録       ↓
                       後日、新しい動画ファイルを追加スキャン
                        ↓
                       Web Worker による Full SHA-256 計算完了
                        ↓
                       自動再紐付け処理 (昇格・アトミックマージ)
```

## 5. Multiple Reviewer Aggregation (複数レビュアーのレビュー集約)

同一の動画ハッシュ値に対し、自分（Local Owner）およびインポートした他レビュアー（Imported）のレビューデータが複数存在する場合、エディタ画面ではそれらがマージされて集約表示されます。

* **総合評価の平均点（Average Overall Rating）**: 有効なスコア（1〜5の整数）からオンザフライで算術平均（四捨五入して小数点第1位まで）を算出して表示します。
* **各レビュアー評価のリスト化**: グレード表記（A〜E）および元スコアと共に、誰のレビューであるか（「自分」または他者の「Imported」）をバッジで区別して表示します。
* **タグのマージと Attribution**: 複数ユーザーが付与したタグは表記のゆれ（大文字小文字の違いやNFKC正規化の違い）を統一してマージされ、付与件数（例: `x2`）が表示されます。タグをホバーすると、誰がそのタグを付与したのか（Attribution）がポップアップします。
* **統合タイムライン**: 時系列順（秒数昇順）にマージされたコメント一覧が表示され、同一秒数に重複したコメントがある場合も確定的なソートアルゴリズム（Deterministic tie-breaking）によって一貫した順序で並びます。他者のコメントは編集不可（ゴミ箱などの UI 操作コントロールが非表示）となります。

> [!IMPORTANT]
> **集約されたマージ結果（平均点や統合タグリスト等）はデータベースに保存されません。**
> 各レビュアーごとの個別のレコード（`video_reviews`, `review_tags`, `timeline_notes`）を独立したままで維持し、画面のレンダリング時に純粋関数（Pure Functions）を呼び出して都度算出する設計となっており、データ不整合を防ぎます。

## 6. Pending Shared Reviews (保留レビュー)

インポートした共有レビューの対象動画ファイルが現在ローカルに存在しない（ハッシュ一致するアセットがない）場合、データは捨てられず `pending_shared_reviews` テーブルに保留状態で安全に保存されます。

### 自動再紐付けのトリガー
バックグラウンドスキャンなどで動画ファイルが追加・処理され、**「完全な SHA-256 ハッシュ値（contentHash）」が確定した（`completed` になった）瞬間**に自動的に紐付け判定が行われます。
* 紐付けは SHA-256 完全一致のみで実行されます。
* アセットがまだハッシュ計算中の `provisional`（暫定）状態、あるいはハッシュ重複による `conflict`（衝突）状態、アーカイブ済みの場合は、紐付けは行われず保留状態を維持します。
* ローカルオーナーの既存のレビューデータはマージ・上書きされず、独立したレコードとして登録（共存）されます。

## 7. Data Safety (データ保護設計)

VideoReviewer では、ローカルファーストアプリにおけるローカルユーザーデータの完全性を最優先とし、以下の多重のデータ保護機構を導入しています。

1. **Local Owner レビューの保護**: インポート操作など、外部からのデータ取り込みによって自分のレビューが書き換えられたり消去されたりしないよう設計されています。
2. **Imported データの Read-Only 化**: 共有で取り込まれた他ユーザーのレコードは読み取り専用として UI 上で制限され、誤ってローカル操作で変更されることを防ぎます。
3. **トランザクションのアトミック性 (Atomicity & Rollback)**:
   * インポート処理などの複数レコードにわたる書き込み時、途中で何らかのエラー（ディスク容量上限、メモリ不足等）が発生した場合は、開始直前のメモリおよび `localStorage` スナップショットを使い、**ロールバック**を試みます。中途半端なデータ書き込みによるリレーションの不整合を防ぐ設計です。
4. **Cascade Deletion（カスケード削除）**: 動画アセットが削除された場合、それに紐付くすべてのレビュー（自分と他者両方）、詳細評価スコア、タグ関連テーブル、タイムラインノート、 IndexedDB 内の対応サムネイル画像バイナリを連鎖削除（Cascade）し、データベース内の孤立データ（オーファン）の発生を防ぎます。
5. **重複インポートの排除**: 同じ共有ファイルを複数回読み込んだり、異なるパッケージ経由で同一のレビューが重複して届いた場合でも、`sourceReviewerId + sourceReviewId` を一意キーとして正確に重複検知し、スキップします。

## 10. Backup / Restore

アプリケーションは、 IndexedDB 内の画像バイナリを含め、データベース全体を単一の ZIP ファイルとして一括バックアップする機能を備えています。

* **スキーマのバージョン管理**: 復元時、ZIP 内に含まれるデータのスキーマバージョンがチェックされます。
* **マイグレーション対応**: 過去のスキーマ（Schema v3）のバックアップデータであっても、復元時に自動的に Schema v4（複数レビュアー対応）へのマイグレーションがアトミックに適用され、シームレスにデータを移行できます。
* **ロールバックによる保護**: 万が一、インポート検証や復元中のマイグレーション処理においてエラーが検知された場合、復元前のデータベース状態へのロールバック処理が試行されます。
* **外部 Identity の維持**: 共有レビューによる `sourceReviewerId`, `sourceReviewId`, `sourceCommentId` および `pending_shared_reviews` テーブルの内容も、バックアップ/復元を通じて完全に保持されます。

## 11. Testing (自動テスト)

アプリケーションの堅牢性を保証するため、ヘッドレスブラウザを使用した自動インテグレーションテスト環境を備えています。

* **現在のテスト通過状況**: **389 件すべてのテストが PASS** しています。
* **主要なテストグループ**:
  * `hash`: ハッシュ検証、重複マージ、conflict検証
  * `folder`: フォルダ登録、再接続、再帰スキャン検証
  * `archive`: アーカイブ化、カスケード完全削除
  * `review`: レビュー、詳細項目、IME Enterバグ対策検証
  * `schema`: Schema v4 マイグレーション、複数レビュアー検証
  * `review-share-schema`: 共有 Schema、集約 Pure Functions、バリデータ検証
  * `review-share-import-export`: Export/Import 処理、アトミックロールバック検証
  * `review-share-aggregate-ui`: UI 集約表示、attributions 表示検証
  * `pending-shared-review-linking`: 保留レビューの再紐付け、アトミック昇格検証
  * `tag-management`: タグマスタ管理・削除・整合性検証
  * `custom-poster`: カスタムポスター画像の設定・復元・アトミックマージ・ロールバック・容量バリデーション検証

### テスト実行方法

## 12. Running the App (起動方法)

本アプリケーションは、完全にクライアントサイドのみで動作する静的な Web アプリケーションです。セキュリティ上の制約（Web Worker や一部 API の Origin 制約）のため、ローカルファイルをダブルクリックで開くのではなく、簡易的なローカル HTTP サーバーを立ててブラウザでアクセスする必要があります。

1. **ローカルサーバーの起動**:
   リポジトリのルートディレクトリで以下のいずれかのコマンドを実行します。
   * Pythonを使用する場合:
     ```bash
     python3 -m http.server 8000
     ```
   * Node.jsを使用する場合:
     ```bash
     npx http-server -p 8000
     ```
2. **ブラウザでのアクセス**:
   Google Chrome などの対応ブラウザで以下のURLを開きます。
   [http://localhost:8000](http://localhost:8000)

## 13. Browser / Platform Notes

## 14. Privacy (プライバシー)

VideoReviewer は、**ローカルファーストかつプライバシー保護**に配慮して設計されています。
* 動画ファイル自体や、その評価データが、ユーザーの明示的なエクスポート操作なしに自動的に外部サーバーやクラウドへ送信されることはありません。
* メタデータはブラウザの `localStorage` / `IndexedDB` を利用してローカルに保持されます。

## 15. Roadmap & External Integration (将来の方向性)

VideoReviewerは、高品質な動画評価メタデータ（総合評価、詳細基準、タグ、時系列タイムラインメモ）を完全にローカルで蓄積するコア基盤（ローカルファーストデータベース）としての役割に特化します。

そのため、自然言語検索（Semantic Search）、テキスト埋め込み（Embedding）、およびLLM（大規模言語モデル/Ollama等）連携といったAIベースの高度な検索機能は、**VideoReviewer本体には直接実装しない方針**となりました。

代わりに、VideoReviewerが蓄積した構造化データを外部ツールや別アプリケーションが安全に活用してセマンティック検索等を実現できるよう、以下の外部連携ロードマップを計画しています。

### Phase 1: Structured Logic Search (本体内での論理フィルタ強化)
* 蓄積されたタグ、総合評価、レビュアーID、タイムラインメモのテキスト部分を組み合わせ、ローカルで高速に論理フィルタリング（AND / OR）できる本体内検索機能の改善。

### Phase 2: Open Data Access Layer (外部ツール用データ出力)
* VideoReviewerの持つSchema v4データベースやShared Review Package（JSON形式）を、Pythonスクリプトや外部のローカル検索エンジン（ベクトルデータベース等）へ引き渡すためのエクスポート機能の拡充。
* 外部のEmbedding生成ツールが、動画ファイル名とタイムラインメモを結合してインデックス化しやすいようなフラットなドキュメント定義形式の提供。

### Phase 3: External AI / LLM Integration (外部エージェント連携)
* **LLM / AI エージェントとの結合**: OpenAI APIやローカルOllamaを利用する外部アプリケーションが、VideoReviewerの評価データを背景知識（RAG）として読み込み、「A評価が付いた動画を探して」「〜について言及されているタイムラインシーンを教えて」といった対話型検索を実行できるようにする連携インターフェース。
* **ボット・スマートシステム統合**: LINE / Discordボットやローカルホームアシスタント等の外部エージェントから、VideoReviewerのローカルライブラリデータを参照できるデータハブAPI/統合インターフェース。
