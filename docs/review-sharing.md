# 共有レビュー設計書 (Review Sharing Specification)

本ドキュメントでは、VideoReviewer アプリケーションにおける共有レビューデータ形式（Sharing JSON Package v1）の仕様、およびそのバリデーション・集約ロジックについて記載します。

---

## 1. バージョン管理の分離

共有ファイルのフォーマットバージョンは、データベースのスキーマバージョン（Schema v4）とは**完全に独立して管理されます。**

* **共有フォーマット識別子:** `"video-review-share"`
* **現在のフォーマットバージョン:** `1`

### 分離する理由
データベースの内部スキーマは、アプリの機能追加（ローカルファイルの管理、再生キャッシュ、IndexedDB の内部構造など）によって頻繁に変更される可能性があります。一方で、共有ファイル形式は他ユーザーや他システムとのデータ通信境界となるため、極めて高い後方互換性と安定性が求められます。これらを同じバージョン番号で管理すると、データベース構造が変わるたびにインポート・エクスポート形式のマイグレーションが発生し、互換性を維持するのが困難になります。

---

## 2. エクスポート範囲と制限

共有レビューパッケージへエクスポートする対象は、**ローカルオーナーのレビュー (`origin: "local"`) のみ**です。

* 外部から取り込んだ他レビュアーのレビュー（`origin: "imported"` のレビュー）は、再エクスポートパッケージに**絶対に含めないでください。**
* コピーや転送によるデータの無限増殖・冗長化を防ぎ、データの「出所（オーナー）」を常に明確にするためです。

### 共有データに含まれる情報（エクスポート対象）
* 総合評価 (`overallRating`: 1〜5 整数値または `null`)
* タグ配列 (`tags`: レビュアーと紐付け可能なオブジェクト構造)
* タイムラインコメント配列 (`timelineComments`: 各コメントの stable な一意 ID、タイムスタンプ、コメント本文)

### 共有データから除外される情報（エクスポート禁止）
* 個別評価項目スコア (`stars` / `criteria_ratings`) - 共有対象外
* 自由コメント / 総評コメント (`comment` / `free_comment`) - 共有対象外
* ジャンル定義 (`genre`) - 共有対象外
* 評価テンプレート (`genre template`) - 共有対象外
* 表示用タイトル (`displayTitle`) - 共有対象外
* サムネイル (`thumbnail`) - 共有対象外
* ローカルファイルパス / 相対パス (`localPath` / `relativePath`) - 共有対象外
* File / Directory ハンドル (`file handle` / `directory handle`) - 共有対象外

## 3. SHA-256 による動画照合

動画アセットの同一性確認には、パスやファイル名ではなく、ファイルの全データから算出した **64文字の小文字 16 進数 SHA-256 ハッシュ値 (`contentHash`)** のみを使用します。

* ファイル名やストレージ構成がユーザー間で異なっていても、ハッシュ値さえ一致すれば、インポート時にローカルアセットに対してレビューデータを正しく紐付けることができます。

---

## 4. パッケージ ID と レビュー ID

共有フォーマットでは、2 つの異なる識別子（Identity）を使用します。

### A. パッケージ ID (`packageId`)
共有パッケージ（JSON ファイル）そのものの UUIDv4 です。同じ共有ファイルの多重インポート判定や、一時的なインポートログの記録に利用されます。
> [!IMPORTANT]
> `packageId` はファイル単位の識別子であり、内包される個々のレビューの重複判定の根拠として利用してはなりません。

### B. レビュー ID (`reviewId`)
個々のレビューレコードに紐づく UUID です。`reviewId + reviewerId` を利用することで、同一レビューが異なる共有パッケージ経由で届いた場合であっても、重複（すでにインポート済みであること）を正確に識別し、同一レビューの再取り込みを防ぐことができます。

---

## 5. 重複検出（Duplicate Detection）方針

インポート前に行われる Validation において、以下の重複データが含まれるパッケージは**不正（Invalid）**として拒否します。

1. **同一 videoHash の重複:** 1 つのパッケージ内に、同じ動画ハッシュ値に対する `item` が複数存在すること。
2. **同一 review 識別子の重複:** 1 つのパッケージ内に、同じ `reviewId` + `reviewerId` を持つレビューが複数存在すること。
3. **同一 timeline comment 識別子の重複:** 1つのパッケージ内で、同じ `reviewerId` + `reviewId` + `commentId` の組み合わせを持つタイムラインコメントが複数存在すること。
4. **同一タグの重複:** 1つのレビュー内に、Unicode NFKC正規化および大文字小文字の違いを除去した canonical なタグ表現が複数存在すること（例: "Travel" と "travel" は同一タグと判定され重複エラーになります）。

## 6. 集約（Aggregation）純粋関数

複数ユーザーからインポートしたレビューデータを画面に表示または活用する際、データベースへ永続化（保存）せずに**その場で動的に集約値を計算する純粋関数**を使用します。

### A. 総合評価平均値 (`aggregateOverallRating`)
* 複数レビューから、1〜5 の整数スコアの平均値を算出します。
* 未評価（`null`）のレビューは分母および分子の計算から自動的に除外されます。

### B. タグの統合 (`aggregateTags`)
* 複数レビューに付与されているタグを集約し、重複のない一意なタグリストを返します。
* 各タグには、どの `reviewId` / `reviewerId` がそのタグを付与したのか（Source attribution）が配列として保持され、追跡可能です。

### C. タイムラインコメントの統合 (`aggregateTimelineComments`)
* 複数レビューのタイムラインコメントを時刻（秒）の昇順で並び替えて統合します。
* 同時刻のコメントが存在する場合は、コメント ID またはレビュアー ID で確定的にソート（Deterministic tie-breaking）され、表示順序が常に一定になります。

## 7. エクスポート（Export）処理フロー

エクスポートは以下の手順で安全に実行されます。

1. **対象アセットの選択**: ユーザーが動画一覧からエクスポート対象作品を選択（チェックボックス）。
2. **ハッシュ値検証**: 選択された動画が有効な 64 文字の SHA-256 ハッシュ値（`completed` ステータス）を持っているか検証します。ハッシュ値計算未完了・失敗・プロビジョナル状態の動画はエクスポート対象外（選択不可）とします。
3. **ローカルオーナーデータ抽出**: 選択アセットに対応する `video_reviews` のうち、ローカルオーナー（`origin === "local"`）のものだけを抽出します。他者からインポートしたレビュー（`origin === "imported"`）は一切含めません。また、個別評価星数、自由コメント、ファイルパス等のプライベート情報は除外されます。
4. **パッケージバリデーション**: ダウンロード用 JSON ファイルを作成する前に、内部で `validateSharedReviewPackage()` を実行して、出力される JSON が Schema v1 仕様を満たしているか自己検証します。
5. **JSONダウンロード**: 検証通過後、`reviews-share-[packageId].json` としてダウンロード保存します。

---

## 8. インポート（Import）処理フローとデータ保護

インポート処理は、外部から取り込まれたデータがローカルデータやデータベースの整合性を壊さないよう、以下の原則に基づいて設計されています。

### A. インポート手順
1. **JSON ファイルのパースとバリデーション**: ファイルが選択されたら、まず `validateSharedReviewPackage()` でスキーマおよび上限定数（DoS対策、巨大入力抑制等）の検証を行います。この検証に失敗した場合、一切のDB操作を行わず即座にエラーで中断します。
2. **プレビュー表示**: 検証成功後、モーダルウィンドウにてインポート対象プレビューを表示。ユーザーはインポートしたいアセットを個別に選択できます。
3. **アセット照合 (SHA-256)**: アセットの照合は、タイトルやファイル名ではなく、完全一致する `contentHash`（SHA-256）のみで行います。
   - **一致アセットあり**: アセットに紐付く `origin = "imported"` の shared review として DB に登録します。
   - **一致アセットなし (Pending)**: 後日アセットが追加されてハッシュ計算が完了した際に紐付けられるよう、`pending_shared_reviews` テーブルに保存します。
4. **インポート結果サマリー**: 処理完了時に、インポート成功・保留・重複スキップなどの内訳数をユーザーへ表示します。

### B. ローカルオーナー（Local Owner）データの保護
* **上書き・マージの禁止**: インポートされたレビューデータによって、ローカルオーナーのレビュー（`isLocal: true` のレビュアーに属するデータ）が更新・マージ・削除されることは絶対にありません。
* **レビュアー ID 衝突回避**: 万が一、インポートパッケージ内に定義されているリモートレビュアー ID が、ローカルアセットのオーナーレビュアー ID や既存の他レビュアー ID と重複している場合、自動的にローカル primary key (`reviewerId`) を再採番して紐付け、オーナー権限の不正奪取や属性上書きを防止します。

### C. データの編集制限 (Read-Only)
* インポートされた他者のレビュー（`origin: "imported"`）およびそれに関連するタグ、タイムラインコメントは、アプリケーション上では**読み取り専用（Read-Only）**として扱われます。既存の Review Editor UI は引き続きローカルオーナーのレビュー編集専用として保護されます。

---

## 9. 重複登録の排除 (Duplicate Prevention)

* **判定ロジック**: 同一レビューが別パッケージ経由で複数回インポートされるのを防ぐため、重複判定のプライマリキーは **`sourceReviewerId` + `sourceReviewId`**（共有パッケージに含まれる元々のレビュアーIDとレビューID）を使用します。
* **パッケージIDによる判定の禁止**: パッケージごとに新規生成される `packageId` を判定基準にしてはなりません。同じレビューデータが別パッケージで送られてきた場合でも正しく重複を排除するためです。
* 重複と判定されたレビューは、データベースおよび Pending 領域への追加をスキップし、インポートサマリーで重複スキップ数としてカウントされます。

---

## 10. トランザクションと原子性の保証 (Atomicity & Rollback)

インポート中に予期せぬエラー（メモリ不足、localStorage 上限、キーの衝突など）が発生した場合に備え、以下のロールバック機構が備わっています。

1. **インメモリ・ローカルストレージスナップショットの取得**: インポート処理を開始する直前に、現在のデータベーステーブル配列（`reviews`, `reviewers`, `reviewTags`, `timelineNotes`, `pendingSharedReviews`, `tags`）のディープコピーおよび対応する localStorage の状態を記録します。
2. **Try-Catch による保護**: インポート処理中に例外が発生した場合、即座に catch ブロックへ遷移します。
3. **ロールバックの実行**: catch ブロックにてスナップショットからメモリ上の配列を完全に復元し、復元された配列で localStorage を一括上書き保存します。これにより、データの一部だけが中途半端に書き込まれた状態（オーファンデータやリレーション破損）を完全に防止します。

## 11. 複数レビュアーのレビュー集約表示UI

他レビュアーからインポートされたレビューが存在する動画をエディタで読み込んだ際、ローカルオーナーのレビューと他ユーザーのレビューが自動的に集約されて表示されます。

### A. 集約値のオンザフライ（都度）計算
データベースに集約後の値（平均評価点、マージされたタグ、マージされたタイムラインコメント、レビュアー人数）を**一切保存しません。** すべて画面描画のタイミングで、データベース内の元の複数レビューデータから純粋関数（`aggregateOverallRating`, `aggregateTags`, `aggregateTimelineComments`）を用いて都度算出します。

### B. UI上の表示仕様
* **総合平均評価**: 有効な総合評価点（整数1〜5）のみを分母・分子として計算し、「4.3 / 5」のように実数表現で表示します（小数点第1位で四捨五入）。
* **レビュアー別評価一覧**: レビュアーの表示名（`displayName`）と、各レビュアーごとの総合評価（グレード表記：A〜E、および元の数値スコア）を表示します。また、ローカルオーナーのレコードには「自分」バッジ、インポートされた他者のレコードには「Imported」バッジを付与し、明確に視覚的な区別を行います。
* **統合タグ**: 同じタグは canonical（NFKC正規化＋大文字小文字の違い排除後）な表現に基づいて1つにマージされ、付与件数（例: `x2`）をバッジとして表示します。また、タグチップをホバーすると、そのタグを付与したレビュアーの表示名一覧（Attribution）がツールチップとして表示されます。
* **共有タイムライン**: ローカルオーナーおよび他ユーザーが作成したタイムラインコメントが、再生位置（秒）の昇順で並び替えて表示されます。時刻クリックによる該当場面へのシーク（Timeline jump）に対応しています。

### C. データの保護と読み取り専用 (Read-Only) の厳格化
* 共有レビュー欄に表示される他者のタイムラインコメントやタグには、削除ボタン（`🗑️` などのゴミ箱アイコン）や編集用の入力欄などの UI コントロールを一切表示しません。
* ユーザーによるタイムラインコメントの追加・削除やタグの追加・削除などの操作は、引き続きローカルオーナーのレビューデータのみに作用し、インポートされた他ユーザーのレビュー（`video_reviews`, `review_tags`, `timeline_notes` 等のテーブルレコード）を書き換えないことが保証されます。

## 12. 保留された共有レビュー（Pending Shared Review）の自動再紐付け処理

インポートした共有レビューの対象動画がローカルに存在しない場合、データは一度 `pending_shared_reviews` テーブルに保留（Pending）状態で保存されます。その後、対象動画が登録されたりハッシュ値が特定されたタイミングで、自動的に通常のインポート済みレビュー（`imported` origin）へと昇格・再紐付けが行われます。

### A. 再紐付けの対象とマッチングキー
* **厳格なハッシュ値照合**: マッチングには、動画ファイルの SHA-256 ハッシュ値（`media_assets.contentHash`）の完全一致（64文字の16進数英数字）のみを使用します。quickHash、ファイル名、ファイルサイズ、相対パスなどの曖昧な情報による照合は一切行いません。
* **Provisional（暫定状態）の除外**: ハッシュ値計算が完了する前の暫定状態（`identityStatus === 'provisional'`）やハッシュ値衝突（`identityStatus === 'conflict'`）、アーカイブ化された動画（`isArchived === true`）に対しては、自動紐付けを行わず保留状態を維持します。確定的かつアクティブな実動画が特定された段階でのみ紐付けを実行します。

### B. 自動紐付けの発火ポイント
1. **Full SHA-256 確定時**: バックグラウンド等でのハッシュ値計算が完了し、`hashStatus === 'completed'` になった直後。
2. **新規動画追加時**: 動画の登録時点で有効なフルハッシュ値が既にセットされている場合。
3. **アーカイブ/再スキャン復元時**: フォルダの再スキャン等により、既存の動画アセットが同じ SHA-256 でアクティブに復元された場合。

### C. データの保護とアトミック性（Atomicity）
* **ローカルオーナーデータの保護**: 再紐付け処理においても、ローカルオーナーのレビューデータ（`isLocal === true` の reviewers, reviews, tags, timeline notes 等）は絶対に書き換えられず、完全に共存します。
* **重複登録の防止**: インポート予定 of `sourceReviewerId + sourceReviewId` を持つレビューがすでに該当動画に存在する場合、紐付けはスキップされ、保留レコードは安全に削除されます。
* **トランザクションのアトミック性**: 個別の保留アイテムの紐付け処理中にエラーが発生した場合、データベースのロールバック機能（`rollbackTransactionSnapshot`）を使い、該当アイテムの追加操作（レビュアー作成、レビュー登録、タグ紐付け、タイムラインメモ登録）をすべて破棄して保留状態を維持します。途中の半端なデータのみが残ることはありません。
